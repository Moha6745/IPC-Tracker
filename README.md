# نظام تتبّع مراحل المستخلصات — IPC Tracker

صفحة ويب واحدة (`index.html`) لتتبّع مراحل المستخلصات: الاستلام ← المراجعة ← الترجيع للاستشاري ← التسجيل بموارد ← التسجيل باعتماد، مع ملخص وتصدير Excel و PDF وطباعة.

## أوضاع التخزين

| الوضع | متى يعمل | أين تُحفظ البيانات |
|---|---|---|
| **سحابي (Firestore)** | عند وجود إعدادات Firebase صحيحة | Firestore — مشتركة بين كل الأجهزة وتتحدّث لحظياً |
| **سحابي (Claude)** | عند فتح الصفحة داخل بيئة Claude | تخزين Claude |
| **محلي** | عند غياب الإعدادات أو تعذّر الاتصال | `localStorage` في هذا المتصفح فقط |

يظهر الوضع الحالي كنقطة ملوّنة أعلى الصفحة: خضراء = متصل بالسحابة، صفراء = محلي، حمراء = تعذّر الاتصال، ونابضة أثناء الاتصال. النقر عليها يفتح لوحة فيها التفاصيل وإعدادات الاتصال.
في الوضع السحابي يُحتفظ بنسخة محلية احتياطية، فإن انقطع الاتصال أو رفضت قواعد الأمان الوصول يتابع النظام العمل محلياً بدل أن يتوقف.

## خطوات الربط بـ Firebase

1. **أنشئ مشروعاً** في [وحدة تحكم Firebase](https://console.firebase.google.com/).
2. **أنشئ قاعدة بيانات Firestore**: Build ← Firestore Database ← Create database (اختر الموقع الأقرب، مثل `eur3` أو `nam5`).
3. **فعّل الدخول المجهول**: Build ← Authentication ← Sign-in method ← Anonymous ← Enable.
   هذا مطلوب لأن قواعد الأمان في `firestore.rules` تشترط `request.auth != null`.
4. **أضف تطبيق ويب**: إعدادات المشروع (⚙) ← Your apps ← Web (`</>`)، ثم انسخ مقطع `firebaseConfig`.
5. **أدخل الإعدادات** بإحدى طريقتين:
   - املأ ملف `firebase-config.js` في المستودع — يصلح للجميع عند نشر الصفحة.
   - أو من داخل النظام: انقر النقطة أعلى الصفحة ← **إعدادات الاتصال** ← الصق المقطع ← **اتصال** (يُحفظ في هذا المتصفح فقط ويتجاوز الملف).
6. **انشر قواعد الأمان** — من المتصفح، بلا تثبيت أي أداة:
   Build ← Firestore Database ← تبويب **Rules** ← امسح المحتوى ← الصق محتوى ملف `firestore.rules` ← **Publish**.

> مفاتيح `firebaseConfig` عامة بطبيعتها ويراها أي متصفح يفتح الصفحة — ليست أسراراً.
> الحماية الفعلية تأتي من قواعد الأمان، فلا تنشر الصفحة بقواعد مفتوحة.

<details>
<summary>بديل: نشر القواعد بسطر أوامر (اختياري، لمن يفضّله)</summary>

```bash
npm install -g firebase-tools
firebase login
firebase use --add            # اختر مشروعك
firebase deploy --only firestore:rules
```
الإعداد جاهز في `firebase.json`. اللصق من وحدة التحكم يؤدي الغرض نفسه تماماً.

## نقل البيانات المحلية إلى السحابة

عند أول اتصال، إذا كانت في هذا الجهاز مستخلصات محفوظة محلياً، يظهر زر **«رفع بيانات هذا الجهاز (n) إلى السحابة»** في لوحة النقطة. يرفع الزر كل المستخلصات المحلية دفعة واحدة، ويدمج المشاريع والأشخاص المحليين مع الموجودين في السحابة دون تكرار.

## بنية البيانات في Firestore

```
app/config          { rev, projects: [{name, company, type}], people: [string] }
ipcs/{id}           { id, project, company, ipcNo, updatedAt,
                      events: [{id, status, round?, date, person, note}] }
```
`status` من: `receive` | `review` | `returned` | `mawared` | `etimad` | `done`.

`done` («اكتمل») هي المرحلة الختامية التي تقفل دورة المستخلص. وجودها يجعل «تسجيل باعتماد» مرحلة تُقاس مدتها كغيرها، بدل أن تكون نهاية بلا مدة. ومستخلص وصل للاعتماد ولم يكتمل بعدُ يُعدّ **جارياً** وتظهر أيام انتظاره في التحليل.

عند حفظ مرحلة بتاريخ لم يأتِ بعد يسأل النظام «التاريخ لم يأتِ بعد — هل تريد حفظه؟»؛ التاريخ يعني اليوم الذي وقعت فيه العملية، والحقل قابل للتعديل ليغطي التسجيل المتأخر لا المستقبلي.

`type` تصنيف الجهة: `مقاول` أو `استشاري`. لا يُعرض في الواجهة — يُستعمل مُرشِّحاً (زرَّا «نوع الجهة») في صفحة **الملخص والتحليل**. `rev` رقم إصدار الإعدادات؛ عند فتح إعدادات أقدم يصحّح النظام التصنيفات من الجدول المرجعي في `PROJECT_TYPES` ويضيف المشاريع الناقصة مرة واحدة.

## التحليل

كل المقاييس مشتقّة من تواريخ المراحل المسجّلة، بلا حقول إضافية:

| المقياس | التعريف |
|---|---|
| متوسط مدة الإنجاز | من أول مرحلة إلى أول «اكتمل» — للمكتملة فقط |
| متوسط أيام المرحلة | من تسجيل المرحلة إلى تسجيل التي تليها |
| نسبة المرتجعة | حصة المستخلصات التي فيها مرحلة «رجعت للاستشاري» مرة على الأقل |
| مرات الترجيع لكل 10 مستخلصات | إجمالي مرات الترجيع ÷ عدد المستخلصات × 10 — ليُقرأ عدداً مفهوماً بدل كسر صغير |
| متوسط التنفيذ | للمسؤول: الأيام بين تسجيل المرحلة السابقة وتسجيله هو للمرحلة. ولا تُحسب له أول مرحلة في المستخلص، ولا «اكتمل» فهي تسجيل ختامي لا عمل تحته |
| أيام الانتظار | لمستخلص جارٍ: من آخر مرحلة سُجِّلت إلى اليوم — يظهر في «الأطول انتظاراً الآن» و«عنده الآن» |

الأقسام: متوسط الأيام في كل مرحلة، الأطول انتظاراً الآن، مقاول مقابل استشاري، أداء المسؤولين (والضغط على أي مسؤول يفتح صفحته بمستخلصاته وتفاصيلها)، ومصفوفة متوسط التنفيذ لكل مسؤول في كل مرحلة.

التحليل في أسفل صفحة **الملخص والتحليل** نفسها، مطويّاً خلف زر «إظهار التحليل» (والاختيار يُحفظ في المتصفح)، ويحسب **المستخلصات المعروضة في الجدول وحدها** — فمُرشِّحات الصفحة (بحث، المشروع، المسؤول، المرحلة، نوع الجهة) تحرّك الجدول والأرقام معاً. وعند تحديد نوع جهة واحد تختفي بطاقة المقارنة لأنها بلا معنى.

## النشر

الرابط المعتمد — **GitHub Pages**، ينشر تلقائياً مع كل دفعة إلى `main`:
<https://moha6745.github.io/IPC-Tracker/>

> نطاق `moha6745.github.io` مُضاف في Firebase ← Authentication ← Settings ← **Authorized domains**،
> وبدونه يفشل الدخول المجهول فيعمل النظام محلياً على المتصفح وحده. فإن نشرت الصفحة على نطاق آخر، أضفه هناك.

**محلياً**: `python3 -m http.server` ثم افتح العنوان في المتصفح (فتح الملف مباشرة بـ `file://` يعطّل تحميل `firebase-config.js` في بعض المتصفحات).

**Firebase Hosting** غير مستعمل. إعداده باقٍ في `firebase.json` لمن أراد نشراً يدوياً بـ `firebase deploy --only hosting`، أما استضافة الصفحة فتكفي من GitHub Pages. (Firestore — قاعدة البيانات — شيء آخر، وهي المستعملة فعلاً.)

## الملفات

| الملف | الغرض |
|---|---|
| `index.html` | التطبيق كاملاً — الواجهة والمنطق والتصدير |
| `firebase-config.js` | مفاتيح مشروع Firebase (عامة) |
| `firestore.rules` | قواعد أمان Firestore — انسخ محتواه والصقه في تبويب Rules بوحدة التحكم |
| `firestore.indexes.json` | فهارس Firestore (لا يحتاج النظام فهارس مركّبة حالياً) — يلزم فقط لمسار سطر الأوامر |
| `firebase.json` | إعداد قواعد Firestore وفهارسها (وفيه إعداد استضافة Firebase لمن أراد نشراً يدوياً) |
| `.firebaserc` | ربط المستودع بمشروع `ipc-tracker-daa8e` |
